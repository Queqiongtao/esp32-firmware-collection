# Wireless Display 协作规则

## 当前阶段

- 当前工程处于 `WDP 1.0` 协议设计阶段，只包含文档和协议模式，不包含可运行实现。
- 未经协议评审，不得提前实现平台客户端、设备固件或私有媒体分片。
- `protocol/wdp.cddl` 是 DataChannel 消息结构的权威来源；文档示例、参考核心和平台实现必须与其一致。

## 设计原则

- 协议使用能力驱动的对等端模型，不写死 PC、手机、RK 或 ESP32 角色。
- WebRTC 负责媒体传输、加密、时钟、拥塞控制和丢包恢复；WDP 不重复定义 RTP 或媒体分片协议。
- 信令与 DataChannel 应保持平台无关，平台限制只能出现在能力声明或平台能力档中。
- 新增消息、字段、权限、错误码或安全边界时，必须同步更新 `docs/protocol.md`、`protocol/wdp.cddl` 和对应示例。
- 安全相关字段不得仅依赖“可信局域网”假设；首次配对必须验证二维码携带的证书指纹和一次性密钥。

## 文档与语言

- 用户文档使用中文；协议常量、JSON/CBOR 字段、MIME 类型和标准名称保持原始拼写。
- 规范性要求使用“必须”“不得”“应”“可以”表达，避免无法测试的模糊描述。
- 引用外部协议时写明标准或实现边界，不复制一套不兼容的私有定义。

## 后续构建入口

- Rust 参考核心落地后，在本工程目录使用 `cargo test --workspace` 和 `cargo clippy --workspace --all-targets`。
- ESP32、RK 和移动端适配器是独立子工程，各自提供构建说明，不在仓库根目录假定统一工具链。
- Git 提交信息默认使用前缀 `WDP-wireless_display: `。
- 未经用户明确要求，不要执行 `git commit` 或 `git push`；只完成代码修改、构建验证和结果汇报，等用户确认后再提交。
