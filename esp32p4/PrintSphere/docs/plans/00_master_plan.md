# ESP32-P4 迁移总计划

## 目标与范围

在 `esp32p4/PrintSphere` 中将 PrintSphere `v1.6.2` 的完整业务能力迁移到 JC1060P470，并固定使用 ESP-IDF `6.0.1`。迁移包括 Wi-Fi 配网、Bambu Cloud、本地 MQTT、状态融合、AMS、封面、受支持机型的 JPEG 快照、Web Config、音频提醒、电源显示和双槽 OTA。

不在范围内：跟随 PrintSphere 上游新提交、支持其他 P4 板卡、90°/270°竖屏、RTSP 解码、修改 ESP32-C6 固件，以及宣称未经上板验证的能力稳定可用。

## 基线

- 业务：PrintSphere `v1.6.2`，标签提交 `32ad5aeb8b5da999de9d94bd9f4d2ec0f065c609`
- 板级：本仓库 `esp32p4/JC1060P470` 的 JD9165、GT911、ES8311 和 Hosted 配置
- SDK：ESP-IDF `6.0.1`
- 目标：ESP32-P4 V1.0，1024x600 横屏，ESP32-C6 Hosted Wi-Fi
- 许可证：FNCL 1.1，个人非商业用途

## 关键风险

1. ESP-Hosted Host 与板载 C6 固件版本不一致可能导致 RPC 告警或连接失败；必须以 `TRANSPORT_UP` 和实际 STA 数据链路为准。
2. GT911 原生坐标与 1024x600 面板坐标不同，0°/180°均需做九点触控验收。
3. MIPI DSI、PSRAM、LVGL 双缓冲同时占用大量带宽；动画、JPEG 和滑页并发时需观察撕裂、白条和任务看门狗。
4. GPIO52 电池模型是线性估算，且当前没有可靠 VBUS/充电状态输入；只显示检测到的电池电压和百分比，不声明外部供电状态。
5. OTA 已增加 `printsphere_p4` 工程名校验和 bootloader rollback，但仍必须真机验证 P4 分区、错误镜像拒绝和 NVS/LittleFS 保留行为。

## 完成定义

完成迁移必须同时满足：固定环境可重复构建；冷启动和连续重启无崩溃；Hosted STA 可扫描、连接和重连；Cloud/Local/Hybrid 三模式完成数据闭环；所有 UI 页面通过 0°/180°目测和触控；声音、电池、Web Config 与 OTA 通过测试；文档记录固件哈希、日志和已知限制。
